# Research: M2 Mobile Game Table

No NEEDS CLARIFICATION remained after the spec; the items below record the open design points from [design.md](design.md) and the technical choices.

## Decisions

| #   | Topic                | Decision                                                                                                                                                                                                             | Rationale                                                                                               | Alternatives rejected                                                                          |
| --- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 1   | Component reuse      | New phone table components in `apps/mobile`, plain CSS.                                                                                                                                                              | Desktop table is PrimeNG based, 952 lines, layout tuned for large screens; M1 set the no-PrimeNG rule.  | Reuse desktop table (bundle size, layout); responsive desktop table (two layouts in one file). |
| 2   | Shared logic         | Move pure helpers (`seatViews`, `seatAreas`, `nextThrowRisk`, `safeLabel`, `pileLevel`, `playedCards`, `totalCards`, `playerSeats`, `youWon`, `seatName`, `logText`) to `libs/client-core`; desktop files re-export. | Single source for view logic, desktop specs stay green as the regression check.                         | Copy into mobile (drift); move into `game-rules` (it is view logic, not rules).                |
| 3   | Routing              | Own route `table/:id` (session + membership guard); lobby and list navigate there when the game is running; `started` removed.                                                                                       | Smallest change; reload on `table/:id` lands on the table (FR-017).                                     | Phase switch inside `GameLobby` (couples two screens).                                         |
| 4   | Orientation          | Table stays mounted; a CSS `@media (orientation: portrait)` overlay with the rotate message and a Leave button covers it. Lobby and other screens are unaffected.                                                    | State (selection, notice) survives rotation (FR-003); no JS orientation API needed (not on iOS Safari). | Orientation lock API (unsupported on iOS); unmounting the table.                               |
| 5   | Zoom and scroll      | Viewport meta `maximum-scale=1, user-scalable=no`, `touch-action: manipulation` on the table, `overflow: hidden`, `100dvh`.                                                                                          | iOS ignores `user-scalable` partly, `touch-action` prevents double-tap zoom.                            | JS gesture blocking.                                                                           |
| 6   | Safe areas           | `env(safe-area-inset-*)` padding on the table root (`viewport-fit=cover` already set).                                                                                                                               | Native, no JS.                                                                                          | Fixed paddings.                                                                                |
| 7   | Double taps (FR-013) | `MobileSocketService.pending` signal: set on send, cleared on ack or on the next view change; buttons disabled while pending. No optimistic state.                                                                   | Server stays authoritative; stops duplicate intents.                                                    | Debounce timers (racy); optimistic updates (violates I).                                       |
| 8   | Dice roll animation  | Small port of `DiceRollService`/`rollDurations` into `core/dice-roll.ts`: client-only reveal of the server dice; skipped under `prefers-reduced-motion`.                                                             | ~40 lines; desktop service is injected into frontend-only code.                                         | Move to client-core (couples to desktop timing config); no animation (spec asks for it).       |
| 9   | Confetti             | Lazy `import('party-js')` in `core/celebration.ts` on win; reduced motion shows no confetti.                                                                                                                         | Dependency already in root `package.json`; lazy keeps the initial bundle small.                         | New library; static trophy only.                                                               |
| 10  | Turn timer (FR-010)  | Thin bar in the board strip, remaining share from `turnDeadline.at` (server clock offset as on desktop), plus the seconds as text in the last 10 s; ticks via one `interval(250)` signal while a deadline exists.    | Information not by color alone (number + bar).                                                          | Circular timer (needs space); no timer (spec requires visibility).                             |
| 11  | Seat states (FR-010) | Computer: animal name + marker. Replaced human: computer marker plus former nickname in the title. Disconnected (`connected === false`): "offline" marker, dimmed. Gone: struck through.                             | All data is in `GameView`/`SeatView`; no protocol change.                                               | Hiding the states.                                                                             |
| 12  | Leave                | Confirm dialog (seat is handed to a computer), then `leave()` and navigate to `/`. Reachable in the strip and in the portrait overlay. After game over: Leave without confirm.                                       | Matches desktop `leave-game` semantics.                                                                 | Immediate leave (accidental taps).                                                             |
| 13  | Timings              | Notice hold and log reveal use `pacing()` from `game-rules`, same as desktop.                                                                                                                                        | Same pace in mixed games.                                                                               | Own constants.                                                                                 |
| 14  | Style budget         | Split table styles over 5 components to stay under the 4 kb per-component warning.                                                                                                                                   | Budgets are enforced in `project.json`.                                                                 | Raising the budget.                                                                            |
| 15  | Browser support      | Current Chrome Android and Safari iOS; `dvh`, `env()`, `:has()` are not required to be older-browser safe.                                                                                                           | Matches the spec assumption.                                                                            | Older browsers.                                                                                |
